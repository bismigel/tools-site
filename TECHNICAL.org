** 1.3 Trust boundaries

| Boundary                    | What crosses it                   | What is trusted                        |
|-----------------------------+-----------------------------------+----------------------------------------|
| Internet → Cloudflare       | everything                        | Cloudflare terminates TLS; Access decides identity |
| Cloudflare → ingress-nginx  | HTTP, ~Cf-Access-Jwt-Assertion~   | nothing until the JWT is verified in-process |
| ingress-nginx → app pods    | HTTP                              | the namespace is *not* trusted; any pod may forge headers |
| app pod → model provider    | prompts, CV text                  | only ~hire~; named destination, ExternalSecret key |
| app pod → cluster DNS       | DNS                               | the only allowed egress for ~tools-site~ |

#+BEGIN_QUOTE
The residual risk that is written down rather than hidden: NetworkPolicy is namespaced, so any pod in
~apps~ can call either service and can set ~Cf-Access-*~ headers. The in-process JWT verification is
what makes that survivable. Never authorise on the unsigned email header.
#+END_QUOTE

** 3.2 Invariants (startup fails, not a silent drop)

1. Every ~Tool.Name~ matches ~^[a-z][a-z0-9_]{0,63}$~ and is unique.
2. Every ~Input.Name~ matches ~^[a-z][a-z0-9_]{0,31}$~ and is unique within the tool.
3. At most 20 inputs per tool.
4. ~Select~ inputs have a non-empty ~Options~; ~Default~ (if set) is a member.
5. ~Min <= Max~; number ranges are finite and bounded.
6. A ~Gated~ tool is only reachable under ~/lab~ and ~/api/lab~.
7. A tool that fetches at runtime is ~Gated~ and names its egress destination in
   ~docs/design/security.md~ and the NetworkPolicy in the same commit.
8. A tool may read build-time data (FX, tzdata) embedded in the binary; it may not fetch it (FR-1.10).

** 3.3 Validation

| Rule                         | Applies to        | Failure code |
|------------------------------+-------------------+--------------|
| Required field missing/blank | all kinds         | ~bad_input~  |
| Length in runes < Min / > Max| Text, Textarea    | ~bad_input~  |
| Numeric parse failure        | Number            | ~bad_input~  |
| Value outside Min..Max       | Number            | ~bad_input~  |
| Value not in Options         | Select            | ~bad_input~  |
| Unknown field in JSON body   | /api, /mcp        | ~bad_input~  |
| Body > 64 KiB                | every POST        | ~413~        |

Validation runs *before* ~Run~. A ~Run~ function may assume its inputs are valid.

** 4.2 Middleware order

#+BEGIN_SRC text
recover → request-id → access log → security headers → body limit (64 KiB)
        → per-route timeout → route handler
#+END_SRC

- ~request-id~ uses ~CF-Ray~ when present, otherwise a generated ID; it is echoed in error bodies and
  every log line.
- ~recover~ returns a ~500~ envelope with the ~request_id~; stack traces go to the log only.
- Timeouts: 5 s default, 10 s for outbound tools; the context is cancelled before ~Run~ returns.

** 4.4 htmx and no-JS contract

- Form: ~<form method="post" action="/t/{name}" hx-post="/t/{name}" hx-target="#result"
  hx-swap="innerHTML" hx-indicator="#busy">~
- With ~HX-Request: true~ the handler returns the ~#result~ partial only; otherwise a full page.
- Validation failures return *200* with ~data-invalid~ on the form and a visible summary — for both
  htmx and no-JS. htmx does not swap 4xx bodies by default, and two code paths for one outcome is a
  bug waiting to happen (spec FR-2.4).
- No inline ~hx-on~, no inline ~style=~: the CSP is ~'self'~ only.
- Every page and every form works with JavaScript disabled (FR-2.6).

** 5.1 slugify (public, M1)

- *Input:* ~text~ — Textarea, required, 1–5,000 runes.
- *Algorithm:*
  1. Unicode NFKD, drop combining marks (~Crème~ → ~creme~).
  2. Lowercase (no locale-specific rules).
  3. Replace runs outside ~[a-z0-9]~ with a single ~-~.
  4. Trim and collapse leading/trailing/repeated ~-~.
  5. Truncate to 80 runes, then trim a trailing ~-~ again.
  6. Empty result → ~bad_input~ ("Nothing to slugify").
- *Deliberately not:* ~&~→~and~, stopword removal, non-Latin transliteration, uniqueness suffixes.

#+NAME: slugify-vectors
| Input                     | Expected |
|---------------------------+----------|
| ~Hello, World!~           | ~hello-world~ |
| ~  Multiple   spaces  ~   | ~multiple-spaces~ |
| ~Crème Brûlée~            | ~creme-brulee~ |
| ~--Already--Slugged--~    | ~already-slugged~ |
| ~a~ × 200                 | 80 chars, no trailing ~-~ |
| ~!!!~                     | ~bad_input~ |
| ~日本語~                   | ~bad_input~ (documented, not a crash) |

** 5.2 rate_converter (public, M6 — non-negotiable)

*Inputs*

| Input           | Kind   | Required | Rules | Default |
|-----------------+--------+----------+-------+---------|
| ~amount~        | Number | yes      | 0.01 – 10,000,000 | — |
| ~currency~      | Select | yes      | ECB-supported currency | GBP |
| ~period~        | Select | yes      | hour, day, week, month, year | day |
| ~target~        | Select | yes      | ECB-supported currency | GBP |
| ~basis~         | Select | no       | contractor = 8h × 5d × 46wk; employee = 7.5h × 5d × 47wk; custom | contractor |
| ~hours_per_day~ | Number | no       | 1–24 | 8 |
| ~days_per_week~ | Number | no       | 1–7 | 5 |
| ~weeks_per_year~| Number | no       | 1–52 | 46 |

*Math*

#+BEGIN_SRC text
hours_per_year = hours_per_day × days_per_week × weeks_per_year
hourly         = amount / period_hours            (period_hours: hour=1, day=hpd, week=hpd×dpw,
                                                   month=hours_per_year/12, year=hours_per_year)
daily          = hourly × hours_per_day
weekly         = daily  × days_per_week
monthly        = annual / 12
annual         = hourly × hours_per_year

converted = amount × rate[target] / rate[source]   (ECB rates are units per EUR; EUR = 1.0)
#+END_SRC

Rounding: compute at full precision, round half-up for display to 2 decimals; never round
intermediate values.

*FX pipeline*

1. ~.github/workflows/fx-refresh.yml~ fetches the ECB daily XML on a schedule.
2. It writes ~internal/fx/rates.json~ with ~base~, ~date~, ~source~, ~rates~, and commits when changed.
3. The binary embeds the file; the tool never fetches at runtime (ADR-0009).
4. The page always displays the rate date. Older than 7 days → warning line + monitoring alert; the
   page still works.

*Failure modes*

| Condition | Result |
|-----------+--------|
| amount ≤ 0 or > 10,000,000 | ~bad_input~ |
| currency not in the file | ~bad_input~ with the supported list |
| target == currency | works; rate 1.0, no special case |
| hours/days/weeks out of range | ~bad_input~ |
| FX file older than 7 days | result + warning, alert fired |

** 5.3 meeting_planner (public, M6 — non-negotiable)

*Inputs*

| Input        | Kind   | Required | Rules | Default |
|--------------+--------+----------+-------+---------|
| ~cities~     | Text   | yes      | 2–6, comma-separated, matched against an embedded IANA list with aliases | London |
| ~date~       | Text   | yes      | ISO date, today ± 366 days | today |
| ~work_start~ | Text   | no       | HH:MM, interpreted in *each city's* local time | 09:00 |
| ~work_end~   | Text   | no       | HH:MM, after ~work_start~ | 17:00 |
| ~length~     | Select | no       | 30, 45, 60 minutes | 60 |

*Algorithm*

1. Resolve each name to an IANA zone (~time.LoadLocation~); unknown → ~bad_input~ naming the offender.
2. The first city is the *anchor*: it fixes the 24 rows and which calendar day is shown.
3. For each hour 00:00–23:00 in the anchor's local day, compute the instant, then format it in every
   city's zone. A cell whose local date differs gets a ~+1~ / ~−1~ note.
4. Mark a cell *working* when the city's own local time is within ~[work_start, work_end)~.
5. Verdict = maximal contiguous run of hours where *all* cities are working, and the run is at least
   ~length~. Express it in anchor time and in each city's time.
6. No qualifying run → say so, and name the closest near-miss (fewest cities outside their window).
7. If any city has a UTC-offset transition on the date, add a warning naming the city and the change.

*Output order:* verdict line → grid (~Table~) → caveats. On narrow screens the grid scrolls inside
its own card; the page never scrolls sideways.

*Limits:* 2–6 cities (readability and output size), one date, no attendee availability, no calendar
integration, no scheduling.

#+NAME: planner-vectors
| Scenario | Expected |
|----------+----------|
| London + New York, a normal Monday, 09:00–17:00 | overlap 14:00–17:00 London = 09:00–12:00 New York (3 h) |
| London + Sydney, same window | no overlap; near-miss named in both zones |
| London + New York on a US DST transition date | correct grid + a DST warning |
| 1 city / 7 cities | ~bad_input~ |
| unknown city name | ~bad_input~ naming the value |
| date 2 years out | ~bad_input~ |

** 5.4 hire capabilities (private, M9)

/All five are registry tools with JSON endpoints; the chat UI (M10) is only another client./

*** merge_profile

- *Inputs:* ~cv_text~ (Textarea, required), ~profile_text~ (Textarea, required),
  ~profile_url~ (Text, optional — validated and echoed as a source link, *never fetched*).
- *Output:* a ~Table~ with one row per field — CV wording, profile wording, status — plus a
  discrepancy list.
- *Provenance states:* ~agreed~, ~conflict~, ~single_source~, ~missing~.
- *Fields:* name, headline, current role, employers with dates, education, certifications, skills,
  location.
- *Discrepancy kinds:* date overlap, employment gap > 6 months, title mismatch, employer-name
  variant, current-role mismatch, field present in one source only.
- *Hard rule:* it does not pick a winner. A conflict is surfaced, never resolved by the model.
- *Rejected:* fetching the URL (LinkedIn serves a signed-out shell; ~robots.txt~ is ~Disallow: /~ for
  ~User-Agent: *~), scraping, stored sessions, vendor enrichment APIs (ADR-0010).

*** screen_candidate

- *Inputs:* ~job_description~ (Textarea), ~candidate~ (Textarea — the merged profile or the CV),
  ~seniority~ (Select, optional).
- *Output:* ~verdict~ ∈ {~strong_fit~, ~worth_a_call~, ~not_a_fit~, ~insufficient~}; rubric rows of
  {requirement, status ∈ {met, partial, not_evidenced}, quote from the candidate text}; gaps;
  ~not_stated~ list.
- *Hard rules:* no bare numeric score; every ~met~/~partial~ carries a verbatim quote; no invented
  employer, title, date or qualification; silence becomes ~not_stated~, not a guess.

*** interview_kit

- *Inputs:* the screening result (JSON), ~focus~ (Text, optional).
- *Output:* 5–10 questions; each tagged with the gap it probes and what it is testing.
- *Hard rule:* at least one question per gap, no generic question lists.

*** draft_email

- *Inputs:* ~decision~ (Select: next step / hold / reject), ~reasons~ (Textarea), ~tone~ (Select).
- *Output:* subject + body.
- *Hard rules:* no invented facts, no promises about salary or dates, never sends anything.

*** redact_cv (optional)

- *Input:* ~text~.
- *Output:* the same text with emails, phone numbers, URLs, LinkedIn URLs and postcodes replaced by
  ~[redacted]~, plus a count of what was removed.
- *Known limit, stated in the UI:* names cannot be detected reliably.

* 6. API-first contract and MCP
:PROPERTIES:
:CUSTOM_ID: api
:END:
** 6.1 The contract rules

1. Every capability has a JSON endpoint; an HTML-only capability is a defect (FR-8.1).
2. Shapes are the external contract: ~inputSchema~, ~Result~, the error envelope (FR-8.2).
3. Changes are *additive only* — a new optional input, a new result field, a new tool. A breaking
   change needs a new path and an ADR (FR-8.3). No ~/v1~ yet: one consumer, additive rule, revisit
   when a consumer cannot be updated in lockstep.
4. Manifest and schemas are generated from the registry, never hand-written or cached at build (FR-8.4).
5. HTML and JSON return the same result; a divergence is a renderer bug (FR-8.5).
6. API-first ≠ JavaScript-first: no capability may require a browser (FR-8.6).

** 6.2 MCP (M7)

#+BEGIN_SRC json
// POST /mcp — tools/list
{ "jsonrpc": "2.0", "id": 1, "method": "tools/list" }

// POST /mcp — tools/call
{ "jsonrpc": "2.0", "id": 2, "method": "tools/call",
  "params": { "name": "slugify", "arguments": { "text": "Hello, World!" } } }
#+END_SRC

- ~tools/list~ advertises public tools to anonymous callers; gated tools only with a valid Access JWT
  or service token (FR-9.2).
- Schemas are the same objects as the manifest (FR-9.3).
- A gated ~tools/call~ without credentials → ~401~, not ~404~: the endpoint is known, the caller is
  not authorised (FR-9.5).
- Service tokens (~CF-Access-Client-Id~ / ~-Secret~) are accepted *only* on ~/mcp~ and ~/api/lab*~,
  are never treated as a human identity in audit logs, and are rate-limited per token (FR-9.4).
- ~tools/call~ returns the same ~Result~ JSON as ~POST /api/tools/{name}~ (FR-9.6).

* 7. Security
:PROPERTIES:
:CUSTOM_ID: security
:END:
** 7.1 Threat model

| Threat | Why it is real here | Primary control |
|--------+---------------------+-----------------|
| SSRF / open proxy | any future fetching tool | no runtime egress in v1; guarded client + ~Gated~ when introduced |
| Abuse / cost | public tools are free compute | ingress ~limit_req~ 40 r/s; per-tool caps, timeouts, concurrency 4; assistant spend guard |
| Auth bypass / header spoofing | any pod in ~apps~ can set headers | verify the signed JWT, never the email header; fail closed |
| CSRF on gated POSTs | Access auth is a cookie | ~Sec-Fetch-Site~/~Origin~ + per-session CSRF token |
| XSS via tool output | tool output is user-controlled text | ~html/template~ escaping, no raw-HTML field, strict CSP |
| Secret leakage | model API key | ExternalSecret only; never logged, never in ~/api~ |
| Supply chain | modules, htmx, base images | ~go.sum~, ~govulncheck~, digest pins, Renovate, no CDN |
| Information disclosure | errors, logs, enumeration | sentinel errors, path templates in logs, gated tools 404 in the public zone |
| Personal-data mishandling | CVs, LinkedIn text | no storage, no content logging, optional redaction, human decides |

Out of scope, stated rather than pretended: DDoS beyond Cloudflare defaults, compromise of the
cluster, and anything an actor with ~kubectl~ in ~apps~ can do.

** 7.2 Gated-zone authentication

#+BEGIN_SRC text
1. Read Cf-Access-Jwt-Assertion. Missing            → 401
2. Fetch JWKS from https://${CF_ACCESS_TEAM_DOMAIN}/cdn-cgi/access/certs
   cached 1 h; on unknown kid refetch, at most once per minute → still unknown → 401
3. Verify RS256 signature                            → fail → 401
4. aud == CF_ACCESS_AUD                              → fail → 401
5. exp > now - 60 s (leeway), iat not in the future  → fail → 401
6. iss matches the team domain                       → fail → 401
7. sub/email used for audit logging only             (never for authorisation)
#+END_SRC

- ~CF_ACCESS_TEAM_DOMAIN~ and ~CF_ACCESS_AUD~ come from a ConfigMap; neither is secret.
- If either is unset, the gated routes are *not mounted*: ~/lab*~ and ~/api/lab*~ return 404 and
  startup logs one warning (FR-4.3). This is what makes deploying before Access is configured safe.
- ~TOOLS_DEV_INSECURE=1~ bypasses verification locally, refuses to start when
  ~KUBERNETES_SERVICE_HOST~ is set, and logs a warning per request.

** 7.3 CSRF (gated POSTs)

- Require ~Sec-Fetch-Site: same-origin~, or (when absent) an ~Origin~ equal to the configured base URL.
- Require ~X-Tools-CSRF: <token>~; token = HMAC(session id from the JWT ~sub~, per-process secret,
  10-minute validity), issued into the page and echoed by htmx via ~hx-headers~.
- Failure → ~403~ plus a logged ~request_id~. Public POSTs skip the token (no ambient credential) but
  keep the origin check.

** 7.4 SSRF

*In v1 there is no runtime outbound request at all.* FX rates are build-time (ADR-0009), tzdata is
embedded, and the NetworkPolicy egress is DNS-only. When a fetching tool is eventually introduced:

- scheme allowlist ~http~/~https~;
- resolve, reject loopback/private/link-local/multicast/unspecified/ULA, *and dial the vetted IP*
  (defeats DNS rebinding);
- ≤ 3 redirects, re-vetted per hop;
- 5 s total / 3 s connect; 2 MiB body cap; 4 MiB decompressed cap;
- no proxy from the environment; fixed honest User-Agent;
- gated visibility, a named egress destination, and a NetworkPolicy rule in the same commit;
- honour the target's ~robots.txt~.

** 7.5 Response headers (every response)

#+BEGIN_SRC text
Content-Security-Policy: default-src 'none'; script-src 'self'; style-src 'self';
  img-src 'self' data:; font-src 'self'; connect-src 'self'; form-action 'self';
  base-uri 'none'; frame-ancestors 'none'
X-Content-Type-Options: nosniff
Referrer-Policy: strict-origin-when-cross-origin
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Resource-Policy: same-origin
Permissions-Policy: geolocation=(), microphone=(), camera=()
#+END_SRC

HSTS is set at Cloudflare, not in-cluster. Fonts are self-hosted, so ~font-src 'self'~ holds.

** 7.6 Input limits

| Limit | Value |
|-------+-------|
| Request body | 64 KiB (~http.MaxBytesReader~) |
| JSON decoding | ~DisallowUnknownFields~ |
| Text length | counted in runes; per-field ~Min~/~Max~ |
| Inputs per tool | 20 |
| Tool timeout | 5 s (10 s outbound) |
| Concurrency per tool | 4, then ~503~ + ~Retry-After~ |
| Response body (outbound, future) | 2 MiB / 4 MiB decompressed |

** 7.7 Logging

Log fields: timestamp, ~request_id~, method, path *template*, status, duration, tool name, outcome,
~cf_ray~, and for gated requests the JWT ~sub~. Never: query strings, tool input values, tool output,
prompts, model answers. ~hire~ additionally logs token counts and spend, not content.

** 7.8 Secrets and supply chain

- Secrets only via ExternalSecret (Bitwarden): ~MODEL_API_KEY~ (hire), the service token (only if a
  gated tool is ever called by ~hire~). Never in git, CI, ConfigMaps or logs.
- ~go.sum~ committed; ~GOFLAGS=-mod=readonly~; ~GOTOOLCHAIN=local~; ~CGO_ENABLED=0~; ~-trimpath~;
  ~-ldflags="-s -w"~.
- Images pinned by digest; htmx vendored with a ~VERSION~ file; no CDN.
- New dependencies require a row in the dependency table in ~docs/design/security.md~ in the same PR.

** 7.9 Kubernetes hardening (both apps)

#+BEGIN_SRC yaml
securityContext:
  runAsNonRoot: true
  runAsUser: 65532
  runAsGroup: 65532
  fsGroup: 65532
  seccompProfile: { type: RuntimeDefault }

  - securityContext:
      allowPrivilegeEscalation: false
      readOnlyRootFilesystem: true

Plus ~automountServiceAccountToken: false~, requests == limits for memory, 2 replicas, PDB
~minAvailable: 1~, topology spread across nodes, and no ~Namespace~ object (owned by

** 8.1 Exchange rates

#+BEGIN_SRC json
{

** 8.2 Time zones

~import _ "time/tzdata"~ embeds the database in the binary. No host dependency, no tzdata package to
patch, and ~CGO_ENABLED=0~ still works. DST is the database's problem, not ours — we only display the
transition warning.

** 8.3 Prompt fixtures (~hire~)

- 3 job descriptions × 5 CVs, invented or the owner's own. No real candidate data in the repo.
- Properties asserted, not golden strings: quotes for every claim, every gap named, no invented
  facts, ~not_stated~ where the text is silent.
- A prompt edit without a fixture run is an incomplete change.

** 8.4 Personal data

- Nothing is stored: no database, no server-side history, no uploaded files.
- Nothing is logged beyond sizes, timings and token counts.
- Redaction is optional (client decision), offered, tested, and warned about when contact details are
  detected. Names cannot be detected reliably; the UI says so.
- A LinkedIn profile is accepted only as pasted text; ~profile_url~ is cited, never fetched (ADR-0010).
- A human sends every email; there is no automated rejection or bulk run.

* 9. Deployment and operations
:PROPERTIES:
:CUSTOM_ID: deploy
:END:
** 9.1 Image

#+BEGIN_SRC dockerfile
# syntax=docker/dockerfile:1
FROM golang:1.27-alpine@sha256:<pin> AS build
WORKDIR /src
ENV CGO_ENABLED=0 GOFLAGS=-mod=readonly GOTOOLCHAIN=auto
COPY go.mod go.sum ./
RUN go mod download
COPY . .
RUN go build -trimpath -ldflags="-s -w" -o /out/toolsd ./cmd/toolsd

FROM gcr.io/distroless/static-debian12:nonroot@sha256:<pin>
COPY --from=build /out/toolsd /toolsd
USER 65532:65532
EXPOSE 8080
ENTRYPOINT ["/toolsd", "-addr=:8080"]
#+END_SRC

No shell in the runtime image, therefore no ~HEALTHCHECK~; Kubernetes probes do that job.

** 9.2 NetworkPolicy

~tools-site~: ingress from ~ingress-nginx~; egress DNS only (UDP/TCP 53 to ~kube-system~).
~hire~: the same, plus the model provider host:443 — never a bare ~to: []~.
Add ~monitoring~ on ~:8080~ when ~/metrics~ is exposed (M3/M8).

** 9.3 Edge, in this order

1. Ingress live and answering over ~kubectl port-forward~.
2. Tunnel hostname → ~http://127.0.0.1:32080~.
3. Proxied CNAME to ~<tunnel>.cfargotunnel.com~.
4. Access application (~/lab*~, ~/api/lab*~ for tools; whole host for hire).
5. Add the hostname to ~ingress-host-check~'s hardcoded list.

Reversed order produces a Cloudflare error page that reads like a broken application. A hostname with
no Ingress returns 404 and looks fine from outside; the host-check CronJob exists because that
happened.

** 9.4 ArgoCD

- ~deploy/k8s/~ (kustomize), one Application per app, namespace ~apps~.
- The repo must be in the ~prod~ AppProject's ~sourceRepos~, or the sync fails with
  ~InvalidSpecError~.
- The image tag line in ~deployment.yaml~ is written only by ~release.yml~. Never hand-edit it.
- ~syncPolicy~: automated, prune, selfHeal.

** 9.5 Rollback

| Situation | Action |
|-----------+--------|
| Bad image | revert the bump PR; ArgoCD syncs the previous tag |
| Bad manifest | revert the ~deploy/k8s/~ commit, or ~kubectl rollout undo~ as a stop-gap |
| Broken edge change | remove the tunnel hostname first, then DNS — offline cleanly, no 502s |
| Site must go away | delete the Application (prune), then tunnel row, then DNS |

** 9.6 Monitoring and alerts

| Signal | Source | Alert |
|--------+--------+-------|
| 5xx rate | ~/metrics~ | > 2 % for 10 min |
| p95 latency | ~/metrics~ | > 1 s for 10 min |
| Pod not ready | kube-state | 2 min |
| Ingress host broken | ~ingress-host-check~ CronJob | any |
| FX file age | build metadata | > 7 days |

- Open a PR that updates the image line in ~deploy/k8s/deployment.yaml~ (never a direct push: GH013).

* 18. Local development
:PROPERTIES:
:CUSTOM_ID: dev
:END:
** 18.1 The tension ~//go:embed~ creates

Production wants a single self-contained binary. Development wants to see an edit without waiting.
One variable (~-dev~) reconciles them, and no other code path branches on it:

| Change | Mechanism | Restart? |
|--------+-----------+----------|
| Go source | ~watchexec -r -e go~ rebuilds and restarts (~1 s at this size) | yes |
| Go template | parsed per request from the disk FS | no |
| ~theme/site-scss/custom.scss~ | ~make css-watch~ re-runs the deterministic ~make css~, served from disk | no |
| Static assets (js, img, fonts) | served from disk | no |

In dev the filesystem root is the repo root; the embed FS mirrors the same paths, so ~/t/{name}~
renders identically in both modes. ~-dev~ is the only switch.

** 18.2 ~make dev~

#+BEGIN_SRC makefile
dev:            ## hot reload on :8080
	@scripts/dev.sh

css-watch:      ## re-run the full deterministic css build on change
	watchexec -w theme/site-scss -w theme/hugo-theme-stack/assets/scss -- make css
#+END_SRC

#+BEGIN_SRC bash
#!/usr/bin/env bash
# scripts/dev.sh — one process group, Ctrl-C stops both
set -euo pipefail
trap 'kill 0' EXIT
make css-watch &
watchexec -r -e go -- go run ./cmd/toolsd -dev -addr=:8080
#+END_SRC

** 18.3 Guardrails (spec NFR-8.2, NFR-8.3)

- ~-dev~ **refuses to start** when ~KUBERNETES_SERVICE_HOST~ is set. A dev build cannot be deployed
  by accident, and the refusal is a startup error, not a warning.
- ~/dev/reload~ (the SSE endpoint used for optional auto-refresh) and ~web/static/js/dev.js~ exist in
  the binary but are **unreachable** when ~-dev~ is off: the route 404s and the ~<script>~ tag is not
  rendered. Tests assert both, because "it is only compiled in" is not a control.
- ~dev.js~ exposes ~window.__tools = { list, call }~ for console poking. It is never referenced by the
  production layout.
- The manifests never set ~-dev~; a review of ~deploy/k8s/deployment.yaml~ is the second guard.

** 18.4 WebMCP as the debugging window (M5)

1. ~make dev~, then open ~http://localhost:8080~ in a WebMCP-capable browser.
2. ~navigator.modelContext.getTools?.()~ lists exactly the manifest's public tools — this is the
   assertion that the manifest and the page agree.
3. Execute a tool from the assistant and compare with the HTML form result; they must be textually
   identical (FR-5.5), because both come from ~Result~.
4. In the console, ~window.__tools.call('slugify', {text: 'Hello, World!'})~ uses the same endpoint as
   the shim, so a failure tells you whether the problem is the tool or the browser bridge.

Caveats, stated so nobody plans around them: WebMCP support is experimental and flag/origin-trial
dependent; ~provideContext~ replaces the whole set on every page load; ~getTools()~ is optional and
may be absent. None of this runs in CI.

** 18.5 The no-browser path (NFR-8.5)

#+BEGIN_SRC bash
make list                                  # GET /api/tools | jq
make call TOOL=slugify TEXT='Hello, World!' # POST /api/tools/slugify, prints the JSON Result
curl -sS localhost:8080/api/tools | jq     # the manual version of the above
#+END_SRC

This is the fallback when the browser flag is unavailable, and it is the path CI uses. WebMCP is a
convenience for humans, never the only way to verify a tool.

** 18.6 What not to do

- Do not render the reload script or ~dev.js~ in production. The test in NFR-8.3 is the guard, not
  the comment.
- Do not add a live-reload Go module. ~watchexec~ in the dev shell is 0 lines of runtime cost.
- Do not make WebMCP the only verification path; see 18.5.
- Do not run ~-dev~ against a shared or cluster address. It serves from disk and skips embedding;
  that is exactly what you do not want in front of other people.
